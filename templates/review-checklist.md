# Review Checklist

> 审查方每轮自检用。不是要全填,是提醒「别漏了这些角度」。最终输出走 [固定裁决格式](../conventions/review-protocol.md)。
> 标了前提的项,项目没有那个前提就跳过(前提标签见[全景文档开头](../docs/idea-to-merge.md#怎么用这个仓))。

## 0. 我是对的审查者吗
- [ ] 这个 packet 涉及**运行时实况**(进程、端口、服务管理器、定时任务、真实库)吗?涉及而我在沙箱里 → 看不到的项报「本环境无法验证 + 该跑哪条命令」,**不报阻断**,并建议交给能进真实环境的审查者
- [ ] 这是对上一轮建议的**修法实现**吗?是 → 审的是终版实现本身,不是「方向对了」

## 范围
- [ ] 只审了**这次的 packet**(named diff / commit / 暂存 / 指定文档),没扩成全仓审计
- [ ] 对照了**工单 spec**:diff 有没有超出 / 偏离工单范围(夹带)
- [ ] 对照了**需求复述表**:人拍过的条目有没有被**静默漏掉 / 推迟 / 转二期**(范围漏项 = 阻断)

## 红线(按你项目补充)
- [ ] R1 隔离分支:改动走了 feature/worktree,没直接落主干
- [ ] R2 破坏性命令:有 `rm`/`reset --hard`/删库 等?做了三确认吗?
- [ ] R3 轻描淡写:有没有「已完成 / 没问题」式无证据声明
- [ ] R4 检查与动作同命令:「查在途 → 重启」「核 HEAD → 发布」是不是绑在同一条命令里?守卫命令有没有接管道吞掉退出码?
- [ ] R5 授权:时机类动作(重启 / 发布 / 出包 / 花钱)有人在当前对话里的字面许可吗?不是转述、不是疑问句?

## 保护区
- [ ] 有没有碰生产数据 / 密钥 / 持久状态 / 项目宪法文件?碰了有没有显式点出?
- [ ] `有生产数据` 写生产数据有没有:备份在仓外、影响行数、逆向验证?(WAL 库的备份不能用 `cp`)

## 失败与防护
- [ ] 新增的可触发动作,失败时触发方**看得见回执**吗?(静默失败 = 阻断级)
- [ ] 测试有没有失败路径用例,断言的是回执内容而不是「什么都没发生」?
- [ ] `有部署` 修的是已确诊的生产问题、又要等部署窗口?工单有没有「空窗防护」行?(没有 = 阻断)
- [ ] 有副作用的调用,失败后的重试有没有先读回现状?
- [ ] 改了一处,全仓同类残留 grep 过了吗?(半修)

## 测试
- [ ] `有测试套件` 测试在 worktree 跑的吗?写口绊线 / 仓内落盘监视零命中?
- [ ] 新增了会外呼 / 会花钱的环境变量?加进测试哨兵名单了吗?
- [ ] 测试数字是审查方 / 统筹**自己跑出来的**,不是转述?

## 完成层级
- [ ] 每条「做完了」对应到[完成层级](../conventions/truth-hierarchy.md)——声明的层级有对应证据吗?
- [ ] 有没有把「代码写完」说成「跑通了」
- [ ] `有部署` 「已装载 / 已生效」有三层实据吗(进程启动时刻 / 各仓 HEAD / 生产真输出)?多仓改动是不是每仓都对上了?
- [ ] 口径:模拟器验收 ≠ 人验收;主嫌 ≠ 定案;候选 ≠ 根治;有没有「原因不明」收尾?

## 收工文档(handoff / 看板 / 工单登记)
- [ ] 提交号、班次、数字前后自洽,不夸大
- [ ] 同一事实只有一个权威源,别处是链接不是副本
- [ ] 看板守卫硬失败项为 0(trail / 删除线 / 超长行 / 指针链)
- [ ] 「纯文档」不构成免审理由——照样逐条审

## 真值层级
- [ ] 结论钉在能拿到的**最高层**(代码 / 运行时 > 文档 > handoff)
- [ ] 没有用 handoff / 总结去盖过当前代码

## 输出
- [ ] 裁决三选一(通过 / 需改后通过 / 阻断)
- [ ] 阻断项都带 `文件:行号` + 证据
- [ ] 附了本轮命令清单(亮出你看了什么)
