# 总调度 Skill 骨架

> Claude Code 的 skill 机制:在你项目里建 `.claude/skills/dispatcher/SKILL.md`,把下面骨架拷进去按你项目填。
> frontmatter 的 `description` 就是触发器——CC 匹配到描述里的场景就自动加载全文,不用每场重教。
>
> 用法见[全景文档第 8、9 章](../docs/idea-to-merge.md)和规则库 A13 / A14;统筹的全流程见[流程图 ③](../docs/flowcharts.md)。三个前提:
> ① 这份只在**总调度 session** 触发,执行棒不读它(执行棒不需要知道怎么派活);
> ② **skill 教打法,不教工程事实**——「现在有哪些服务/工单什么状态」这类快照必然过期,一律链接权威源;
> ③ 只有「多 session 并行」才需要它。单线项目别上总调度,多余的层级是纯开销。

# 总调度打法

> 单兵纪律在 <你的打法手册 skill>(先读它);本 skill 只管「多棒统筹」这一层。

## 0. 铁律(违者=白干)

1. **接棒第一动作=汇报,不是干活。** 接手后只做只读核查(先 fetch 主干再读工单
   ——执行棒的回写都在主干上,不 fetch 就按旧状态重做=重复劳动;只读核查前先确认
   要碰的「查」类接口真只读,假只读件名单见 <权威文件>),核完先向维护者汇报现状
   与打算,拍了才开工。**服务对象是维护者,不是上一棒**:交接 prompt 与人现场说的
   冲突,以人为准。
   **汇报必含一条硬项:逐条点名台账里拖龄超期的已拍板件,今天排不排**——排就给
   排期,不排写理由,不许略过。
2. **派单前先纠漂。** 台账说「待做」≠真待做——先 git log + 运行时核一遍是否
   已完成。判据:代码/运行时 > 现状文档 > handoff。
3. **系统更改→工单当场回写**(整条重写当前态,不追加历史),不攒到收工。
4. **授权边界**:别的 session 转达的「人已拍」只授权「可以排上」,不授权时机;
   「为什么还没 X」是疑问不是命令;时机类动作(重启/发布/出包/花钱)只认维护者在
   当前对话里的字面许可,许可一次一发不留存。
5. <你项目的部署窗口/花钱/危险动作红线,总调度无豁免>

## 1. 盘点(接手第一小时)

看板顶部 → 逐单纠漂 → 分四堆,按序处理:
**已完成只差验收**(最优先,零成本关单)> **有明确手册的机械活**(派棒)>
**设计未冻/核心灵魂件**(总调度自拆,永不外包)> **等人拍的**(列清,不催)。
在途 session 逐个核实,防撞。

## 2. 派棒

- 并发上限:<N> 个执行棒 + <M> 个轻查(只读查证棒);每单预算 = 1 执行 + 1 返工 + 1 收口小修,超了停下报。
- 模型:机械/有手册的实现活=<便宜档>;灵魂层/核心管线=总调度本人,永不外包。
- 派单模板(缺一不可):工单号/目标一句话/必读权威文件/当前真实状态(纠漂后)/
  允许范围/**禁止范围**(生产路径/共享部署位/在途线文件)/执行要求(grep 全改不半修
  + 测试全绿 + 在 worktree 跑)/逐项可验的验收标准(带验证命令+判据)/停止条件/
  **预计时长**(超时=停下报)/返回格式(分支、提交、基于哪个主干、测试数字、是否涉及装载)。
  **末尾必加:全部自己动手,不许再派子 agent。**
- 派单里写明:**不许自己往共享部署位合入、不许出包、不许发布**;要写生产数据先报总调度等回执。
- 认领共享文件:发消息 ≠ 认领成功,**收到回执确认无撞才动手**。
- 契约中途变更→立刻通知受影响的棒,别等它做完再返工。
- **子 session 在途的活,总调度不亲自重复做。** 要改方向=发消息;等不及=先停掉
  那个棒再接手,绝不双线改同一批文件。

## 3. 共享资源(只有总调度能动)

- **共享部署位只由总调度合入**:执行棒报「分支/提交/基于哪个主干/改了什么/测试
  结果/是否涉及装载」,总调度 `merge --ff-only`。部署位上合并≈装载,所以合入前
  就要满足发车条件(第 5 节)。
- **单实例资源排号**:<唯一的模拟器/调试设备/开发服务器端口>按号排队,登记谁在用、
  用完没;用完即关。
- **出包归总调度**:执行棒一律不出包。前置顺序卡死:模拟器跑通 → 汇报维护者 →
  维护者说「可以出包」才出。
- **生产数据写入**:执行棒先报(维护者原话 + 仓外备份路径 + 影响行数),总调度核
  有没有撞车(同库在途写、正在装载的进程)后回执放行;改完要逆向验证。

## 4. 验收环(每棒回报走一遍)

1. 亲手复测(测试数字自己跑出来,不信自述)+ diff 范围核(越界=返工)+ 需求复述表
   核(拍过的项有没有被静默漏掉)。
2. 递审查方互审:纯代码 diff → <异构审查方,如 Codex,单独前台跑 + `< /dev/null`>;
   涉及运行时实况 → 能进真实环境的审查者(订阅内子 agent);审查方额度尽 → 订阅内
   子 agent 兜底。回执逐条裁决不盲从——驳回给理由,采纳给精确修法;**修法实现后回递终审**。
3. **返工打回原棒**(上下文还热),消息带具体条目+代码位置,不说「再检查一下」。
4. 收敛后合并:<你项目的合并方式>;生效件登记进发车货单(每件带验证命令+判据)。
5. 功能验收由 AI 自核(模拟器/日志/库/接口),不拿维护者当人肉报错器。

## 5. 发车 / 发布

- 窗口按部署成本选:<贵=冷窗;低=任意静默窗;自动部署=合并即发车>。不管哪档,
  **每一次都要维护者当次点头**。
- 检查和动作同一条命令:`[ 在途=0 ] && 重启`、`[ HEAD==核过的SHA ] && 发布`;守卫命令不接管道。
- 发布前给维护者看得到的东西(截图/预览地址),说「发」才发;中间态不发。
- 装载后三层验证:进程启动时刻 / 逐仓 HEAD / 货单逐件生产真输出。

## 6. 对维护者

- 只让人拍五类:要不要/往哪走/像不像/花不花钱/碰没碰红线。
  排期/工序/派棒时机=总调度直接定+告知,不许抛回。
- 汇报三段式:结了什么/在途什么/等人什么。要人跑的命令置顶单独块。
- **交接前必须先走完收工 checklist**——handoff 只是其中一步。
- 交接里的「在途棒」必须说人话:挂在哪/产物在哪/什么状态/下一棒该等它还是接管它。

## 7. 收尾清理

- 执行棒合入后负责清自己的 worktree;删之前两道预检:
  ① `lsof -a -d cwd -u $USER` 有进程的工作目录在此 → 拒;
  ② `git status --porcelain --ignored=matching` 过滤可再生文件后仍有 `!!` 行 → 拒并列出。
- 批量清理走脚本(绝对路径数组、拒删主仓与当前 session、HEAD 必须是主干祖先、先干跑),
  跑前让另一个模型复核;worktree 只删自己开的。
