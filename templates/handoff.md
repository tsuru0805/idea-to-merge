# Handoff 模板

> 交接给下一个会话(可能是几小时后、也可能是另一个人 / 另一只 agent)。
> handoff 是**历史线索,不是现状事实**——下一棒读它知道「上一棒做到哪、为什么这么做」,但关键事实要按[真值层级](../conventions/truth-hierarchy.md)回代码和运行时核,别照抄。
> handoff 是收工 checklist 的一步,不是全部:**交接 = 先收工**。写完后和看板改动、工单更新**整批过一次审查**再 commit / push(它最容易把「打算修的」写成「已修」);没有免审例外。
> 多棒同日各自收工时,文件名加主题后缀防撞:`handoff-YYYY-MM-DD_<主题>.md`。找最新交接 = 按文件名日期取最新那一天,同日多份按主题并列读,不需要索引。

---

# Handoff · YYYY-MM-DD · <主题>

## 这次做了什么
<时间线 / 改动概览。提交号、PR 号写准。>

## 关键决策点
<为什么这么选,不那么选。下一棒最需要知道的「为什么」。人当场拍的板,写人的原话。>

## 范围守恒(收工第 0 步)

<!-- 今天有没有把人拍过的任何范围切小、推迟、转成「二期 / 欠账 / 等拍」?
     有就逐条写在这里,并写进给人的收工总结。只有物理原因合法(等部署窗口 / 外部依赖 / 等人在场),
     「工作量大 / 先做核心」不合法。没有就写「无」。 -->

- <无> / <工单 X 的第 N 项推迟,原因:……,人已拍 / 待人拍>

## 完成层级(逐层说清,别含糊)
- 代码:✅ / ❌
- 测试:✅ / ❌(数字:<N passed>,在哪个目录跑的)
- 已 commit:<hash 或 ❌>
- 已 push / 同步:✅ / ❌
- 已装载:✅ / ❌ / 候装载(进程层:<进程启动时刻> · 代码层:<各仓 HEAD == 钉货 SHA>)
- 已生效 / 运行时已验证:✅ / ❌(产出层:<一条生产真输出>)
- 用户体感已验证:✅ / ❌
- 长期观察:✅ / ❌ / 不适用

> 「已装载」= 进程层 + 代码层两项实据齐;「已生效」= 再加产出层。实据不够就写「候装载 / 候验证」。

## 装载守恒(收工第 0.5 步)

<!-- 仅「有部署」的项目需要。今天有没有产生候车货(合了主干、要等部署才生效)? -->

- 候车货:<无> / <清单,每件带验证命令 + 通过判据>
- 下一班车:<已挂,任务名 X,两处核过> / <无车,货 X 顺延,原因 Y>

## 踩了什么坑
<别人(包括未来的你)能少踩一次的东西。沉淀成规则的,写「已写入 <权威文件>」,这里不复述全文。>

## 待验收(验过即销)

<!-- 部署完 ≠ 做完。分两栏:功能层 AI 自己证明,人只验 AI 验不了的。 -->

**第一栏 · AI 自核**:
- [x] <验了什么> — 证据:<截图路径 / 日志行 / 查询结果 / 接口返回>
- [ ] <只能等自然使用才出现的> — 静默窗自核计划:<等它自然发生一次后,下一棒查哪个日志 / 哪张表>

**第二栏 · 留给人的体感项**(每项傻瓜级,一步操作;没有就写「无」):
- [ ] <验什么> — 怎么验:<打开哪 → 看哪> — 预期:<看到什么算过>

     不许写「在途三个执行棒,新棒直接验收」这种分不清「验收现成产物」还是「别动、人家还在做」的话。 -->

| 会话 / 子 agent | 挂在哪(worktree / 分支) | 产物在哪(提交号) | 现在什么状态 | 下一棒该等它还是接管它 |
