# 收工 Checklist Skill 骨架

> 拷进你项目的 `.claude/skills/shutdown-checklist/SKILL.md`,按你项目填。
> 收尾是 AI 最容易「总落下这个那个」的环节——这份 checklist 就是对治。
> 关键设计:**触发词写进 description**(人说「收工」就自动走)+ **交接前也强制触发**
> (没走完 checklist 的交接 = 没交接,下一棒拿到的是一地散件)。

---

```markdown
---
name: shutdown-checklist
description: 每日收工流程。当维护者说"收工""今天到这""结束""下班"或任何表示
  当天工作结束的话时触发;**任何交接/传棒/handoff 前也必须触发**(交接=先收工,
  不许光扔一份 handoff 就走)。触发后严格逐条执行,不准偷懒不准跳步。

# 收工 checklist(喊"收工"或任何交接前必做)

> 每条都要过,过不了的明说为什么。

1. **handoff-YYYY-MM-DD.md** 新建今天的交接条:时间线 + 决策点 + 踩坑 +
   **待验收区**(验什么/怎么验/一步操作)+ 未完成项。
   多棒同日各自收工时,文件名加主题后缀防撞(`handoff-YYYY-MM-DD_<主题>.md`)。
2. **todo 看板**按规约维护,四个动作:
   - **改**:推进过的单,看板行**整条重写**为当前态(新态替换旧态,禁划线/日期链);
   - **关**:完成的移「已完结」表一行;
   - **钉**:自己的在途挂牌行收工即删;临时行逐条核对删除条件;
     欠账做完**删行**,拖龄超 3 天的收工总结里逐条点名;
   - **量**:跑看板守卫脚本(行数/体积),输出贴进收工总结。
3. **工单文件**:当天推进过的,状态/步骤当场更新。
4. **服务表**:新增/搬家/下线/端口变 → 更新权威总览 + 对应服务文件。
   <没有服务表的项目删掉本条;有的话:新增服务两件套缺一不算完成>
5. **架构文档**:结构/数据流/命名约定变了才更新对应区块;不写流水账,写当前结构。
6. **memory**:今天沉淀的教训写成 feedback 条目(是什么+为什么+下次怎么做);
   **改 memory 文件必须同步改索引行**——不进索引的 memory 等于没写。
7. 仓内改动 **commit + push**——只提交本棒范围内的改动(先 `git status -s` 核清单,
   别把别棒的 WIP 一起收走);push 失败不硬解,汇报现场。
8. 给维护者一条**收工总结**:今天做了什么 / 待验收什么 / 明天从哪接。

## 月度归档巡检(每月初一次,非每日)

9. handoff 活区只留当月,更早的移进归档区(进去即冻结,只查不改);
   已完结工单随巡检归档。**归档前先 grep 代码里有没有脚本在读该文件**
   ——工单完结 ≠ 文件可挪,断粮事故就是这么来的。
```
