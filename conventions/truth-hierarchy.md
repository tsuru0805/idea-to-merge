# 真值层级 + 完成层级

两套「层级」是这套工作流防「假装做完」的核心工具。

---

## 真值层级(claim 冲突时信谁)

不同来源说法打架时,**高层覆盖低层**:

1. 当前代码、目标 diff、运行时输出、命令直出结果
2. 现状文档(current-state)
3. Codex review
4. 最新 handoff
5. 更旧的 handoff
6. agent 总结

**用法**:审查方的结论必须钉在**能拿到的最高层**。低层只能当背景,不能推翻代码 / diff / 运行时 / 直接验证。
「上一份 handoff 说已经修了」**不能**盖过「现在代码里没看到这段修改」。

**为什么**:文档会漂、handoff 是历史线索不是现状事实、总结会美化。能跑命令核的就别信文档。

---

## 完成层级(「做完了」到底做到哪一层)

「做完了」不是一个状态,是**八个递进的层级**。声明只能认到有证据的那一层,缺的层级要**明说缺**,不能默认它完成:

| 层级 | 证据长什么样 |
|---|---|
| 1. 代码存在 | diff / 文件里有这段 |
| 2. 测试通过 | 测试输出 |
| 3. 已 commit | commit hash |
| 4. 已 push / 同步 | 远端有 / 同步确认 |
| 5. 已 reload / 部署 | 部署动作发生过 |
| 6. 运行时已验证 | 真跑了一次、看到预期行为 |
| 7. 用户体感已验证 | 人真用过、确认对 |
| 8. 长期观察 | 跑了一阵、没复发 |

**用法**:写汇报 / handoff / commit message 时,逐层说清。比如:

> 完成层级:代码 ✅ 测试 ✅ 已 commit ✅ / 运行时**未验** / 用户体感**未验**。

而不是一句含糊的「搞定了」。

**为什么**:最常见的事故是把第 1 层(代码写完)说成第 6 层(跑通了)。
把层级拆开,「打算做的」和「真做完的」就藏不住了。

### 第 5、6 层再拆细:装载三层

`有部署` 的项目,「已部署 / 已生效」本身也要拆:

| 说法 | 需要的实据 |
|---|---|
| **已装载** | ① 进程层:该重启的每个进程,启动时刻 = 这次发车时刻(`ps -eo pid,lstart,command`)<br>② 代码层:**逐仓** `git rev-parse HEAD` == 货单钉的 SHA |
| **已生效 / 已上线** | ①② 之外,③ 产出层:货单逐件一条**生产真输出**(判据在货单登记时写好) |

- 多仓改动只装了一仓 = 没装载;共享模块只重启了一个宿主进程 = 没装载。
- 产出层判据钉在**用户真正在用的那条链路**上。
- 实据不够就写「候装载 / 候验证」。handoff / 看板里的「已装载」一律当**待核声明**,下一棒拿运行时复核后才准往下接。

### 第 7 层的分工

「用户体感已验证」只留给 AI 验不了的部分(体感、审美、像不像)。功能对不对属于第 6 层,由 AI 自己拿证据证明——**模拟器验收 ≠ 人验收**,两层分开写。

---

## 结论口径(排查 / 审计类)

排查报告和事故复盘里的结论,按证据强度分三层标注,不混写:

| 层 | 含义 |
|---|---|
| **确证** | 对账到数、复现过、日志实证 |
| **高置信推断** | 证据链完整但缺一环直接观测 |
| **待探针** | 现有观察面钉不到 |

配套口径:**主嫌 ≠ 定案,候选修法 ≠ 根治**。禁止以「原因不明 / 不知道为什么」收尾——解释不了,说明观察面缺了,改写成「缺 X 探针,补法 + 成本如下」。看率类、成本类问题,窗口默认 ≥ 7 天。

---

## 审查方怎么用这两套

- 拿到一份汇报 / handoff,逐条问:**这句声明对应哪个完成层级?有那一层的证据吗?**
- 声明的层级 > 证据的层级 → **阻断**或**需改后通过**,把措辞改回准确层级。
- 同一个 agent 自己写声明、自己审自己 → 不算独立验证,这正是要异构对抗的原因。
- 「已装载 / 已生效」缺三层实据、「原因不明」收尾、主嫌写成定案 → 按上一条处理:照原样会写出错误记录的 = **阻断**,底层改动没问题、只是措辞越层 = **需改后通过**(判据以 [`AGENTS.md`](../AGENTS.md) 的 When to block 为准)。
