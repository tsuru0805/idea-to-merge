# 给你的 Claude Code 配个监工(Codex)

> 你跟 Claude Code(下面叫 **CC**)结对写代码,但你看不懂它写了啥、也不知道它有没有偷工减料。
> 这套东西就是给 CC 配一个**永远在线、专门挑刺**的 Codex 监工——CC 改完先过 Codex,审到过才放行,然后才轮到你拍板。
>
> **这是人看版。看完觉得能用,把 [机看版](for-claude-code.md) 整个丢给你的 CC,它读完就知道怎么走。**

---

## 什么时候你需要它

1. **CC 抛一堆技术方案,你分辨不了优劣**,只能听它信口雌黄,点头说「那就这样吧」。
2. **你提个需求,CC 改了一大堆**,中间偷偷动了俩变量,代码直接瘫了——你还不知道是哪动的。
3. **CC 嘴上说做 A,实际代码改的 B**,你肉眼根本检查不出来。
4. **你和 CC 脑暴鬼打墙**:这边补上、那边又漏,工程半天推不动。
   （这种时候,直接叫 CC 把你俩的痛点列出来,丢给 Codex 去掰扯。)

只要中了一条,这套就是给你的。

---

## 它做了什么

一句话:**引入 Codex 给 CC 做自动 review,审到过才放行。**

写代码的和审代码的,不是同一个 AI——CC 自己审自己会自我感觉良好,换一个不同牌子的 Codex 来,它才敢挑、挑得动。两个 AI 互相不给面子地对线,**你只当裁判,不当 debugger**。

> 💴 **成本**:Codex 我用的是订阅档(大约 3000 日元/月,按你所在区/档位而定),日常完全够用。
> 跑 review 时**思考深度开【中】(medium)就行**,不用拉满——这类活中等深度足够,又快又省。

## 它做不了什么(实话实说)

- **不保证 AI 不犯错**。它只是让错误在进你手里之前,被另一个 AI 先逮到一批。
- **不是全自动**。两个地方故意留给你拍板:「这事要不要做」和「做完了能收工不」。机器互相说「通过」≠ 这事就该做。
- **小修小补用不上**。改一个字还走这套,开销比收益大。它的价值在**改动大、一改怕塌、你最容易被「已完成」骗**的地方。
- **Codex 也不是神**。它也会看走眼、也会嘴硬。所以裁决要核查、该反驳就反驳——**两边都不无脑信**,目的是把工程推对,不是收集一个「通过」。

---

## 看完想用?

把 **[机看版 `for-claude-code.md`](for-claude-code.md)** 整个复制,丢给你的 CC(或塞进它的 `CLAUDE.md`)。它读完就知道:每做完一段自己调 Codex 审、审过才来找你、裁决写进 commit。

你要做的,就两件:**该点头的地方点头,该打回的地方打回。**

不再一个人对着看不懂的代码 debug 到崩溃——这就是全部。
