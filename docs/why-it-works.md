# 为什么这么设计 + 什么时候别用

## 三层原理

### 1. 异构双模型对抗

单模型自审的根本问题是**自我说服**:同一个模型,刚写完代码、脑子里还是「我刚才那套逻辑」,
让它回头审自己,它会倾向于确认自己是对的——和人写完代码自己 review 抓不到 bug 一个道理。

换一个**不同训练血统**的模型(Claude 做工、Codex 审查),它没有「我刚才那套逻辑」的包袱,
是带着外部视角进来挑刺的。两个模型互不背书,挑得动自审挑不出的洞。

关键不是「Codex 比 Claude 强」或反过来——而是**异构**本身有价值。两个不同的模型对同一段代码的盲区不一样,交叉起来盲区才小。

### 2. 人类闸门

全自动很诱人,但**机器之间互相说「通过」不等于这件事该做**。所以闸门卡在两个**判断题**而非**计算题**上:

- **提案通过**:要不要做、是不是你想要的东西——只有你知道。
- **收工**:这一段到此为止、可以交接了——节奏由你定。

部署之后还有第三个节点——**体感验收**。注意它的分工:功能对不对仍然是计算题,由 AI 自己拿日志、库、模拟器截图去证明;留给人的只有判断题——快不快、顺不顺、像不像。把功能验收也推给人,等于把人当测试机。

中间的「代码对不对、有没有偏离 spec、完成度有没有吹」这些**计算题**,交给机器对抗。
人类不盯每一步,只在该拍板时介入。这是「省人力」和「不失控」之间的平衡点。

### 3. 留痕免维护

任何「需要专门去维护的记录」最后都会漂、会过时、会变成屎山。所以审计轨迹挂在**天生不可变**的东西上:

- 裁决写进 **commit message**(`codex 回执:…`)——git 历史不可改、不漂、零维护。
- **不另写 review 报告文件**——报告文件会像交接文档一样越堆越多,还和代码现状脱节。

只有刻意的里程碑(大型重构 audit)才值一个独立文件。日常 review 一律进 commit message。

---

## 这套**不是**什么

- **不是** Codex 给 Claude 当下属。两个 agent 平级,审查方对**事实**负责,不对做工方的面子负责。
- **不是**全自动 CI。它是「机器对抗 + 人类拍板」,人类闸门是刻意保留的,不是没来得及自动化。
- **不是**「跑一遍就过」。Reviewer 的回执要被核查;Builder 觉得它错了要摆证据反驳。目的是把工程推对,不是收集一个「通过」。

---

## 什么时候别用(诚实的边界)

- **改一个字的小修**:立工单 + 双审的开销 > 收益。直接改。
- **纯探索 / 原型**:还在试方向、随时要推翻,审查没有稳定的 spec 可对照。等定型了再上循环。
- **你比两个模型都懂这块**:你自己 review 更快更准时,别为了流程而流程。
- **两个 agent 死磕**:来回几轮不收敛,说明这是个判断题不是计算题——别让它们空转,交给人。

经验法则:**改动越大、越不可逆、越「我以为我做完了」的地方,这套收益越高**;越小、越可逆、越确定的地方,越是纯开销。

## 它具体防住了什么(真实踩坑归纳)

这套循环是被这几类反复发生的事逼出来的:

- **「轻描淡写」**:做工方总结说「已完成 / 没问题 / 已修复」,实际只写到「代码存在」那一层。
  → 审查方按[完成层级](../conventions/truth-hierarchy.md)逐层核,把「打算做的」和「真做完的」拆开。
- **「候选当事实」**:handoff 里把「准备这么修」写成「已经这么修了」。
  → 审查 handoff 时专盯这个,候选补丁写成事实 = 阻断。
- **「自审自批」**:同一个 agent 写完声明、自己审自己,当成独立验证。
  → 异构对抗从结构上断掉这条:写的和审的不是同一个模型。
- **「默默偏离 spec」**:diff 超出工单范围、夹带没说过的改动。
  → 审查对照工单 spec,超范围就报。
